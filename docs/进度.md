## ⬜ M3 — BLE 发现（下一步）

**目标**：接收方起 GATT Server 并广播，发送方扫描到并读取设备信息

### 接收方（GattServerService）
```java
// 1. 开 GATT server
BluetoothGattServer server = btManager.openGattServer(ctx, callback);
BluetoothGattService svc = new BluetoothGattService(
        BleUtils.SERVICE_UUID, BluetoothGattService.SERVICE_TYPE_PRIMARY);
// CHAR_STATUS: 只读（对外暴露 DeviceInfo）
svc.addCharacteristic(new BluetoothGattCharacteristic(
        BleUtils.CHAR_STATUS_UUID, PROPERTY_READ, PERMISSION_READ));
// CHAR_P2P: 可写（接收发送方的 P2pInfo）
svc.addCharacteristic(new BluetoothGattCharacteristic(
        BleUtils.CHAR_P2P_UUID, PROPERTY_WRITE, PERMISSION_WRITE));
server.addService(svc);

// 2. BLE 广播（ADV_SERVICE_UUID）
AdvertiseData data = new AdvertiseData.Builder()
        .addServiceUuid(new ParcelUuid(BleUtils.ADV_SERVICE_UUID))
        .setIncludeDeviceName(false).build();
advertiser.startAdvertising(settings, data, callback);
```

### 发送方（扫描 + GATT client）
```java
scanner.startScan(filters, settings, scanCallback);   // 过滤 ADV_SERVICE_UUID
// 扫到后 connectGatt → discoverServices → readCharacteristic(CHAR_STATUS)
// → 拿到 DeviceInfo{key, mac} → 算出 cipher
```

### 关键注意点（已踩过或预判）
1. **分块读写**：`DeviceInfo` JSON 可能超过单个 ATT MTU（23 字节默认）。
   CatShare 用 `writeRequests` map + `copyOfRange` 处理分块写入 —— **必须实现**
2. **`onCharacteristicReadRequest`** 要支持 offset 分块
3. `onDescriptorWriteRequest` 要回 `sendResponse`
4. BLE 广播**不需要**配对；但 `BLUETOOTH_ADVERTISE/CONNECT` 权限必须已授予
5. `AdvertiseData` 有 31 字节上限，超了会失败 —— 只放 UUID，不放自定义数据

**参考**：`$HOME/CatShare-src/.../services/GattServerService.kt`（385 行，只读）
         `$HOME/CatShare-src/.../utils/BleUtils.kt`

**验收标准**：两台设备，A 广播，B 能扫到并读到 A 的 DeviceInfo（含公钥）

## 🔑 关键决策

| 决策 | 理由 |
|---|---|
| 纯 Java | 本机无 kotlinc |
| 手写 WebSocket | 无 Gradle，无法引入 Ktor |
| 不用 lambda | 严格 android.jar 缺 LambdaMetafactory（P011）|
| 不用 androidx | 无依赖仓库（Perms 已改为原生 API）|
| 不实现 MAC/root | 协议死字段（P001）|
| 等状态就绪而非等广播次数 | P2P 广播有中间态（P016）|
| app 内置 autotest 入口 | 锁屏无法驱动 UI（P017）|
