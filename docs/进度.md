## 🔑 关键决策

| 决策 | 理由 |
|---|---|
| 纯 Java | 本机无 kotlinc |
| 手写 WebSocket | 无 Gradle，无法引入 Ktor |
| 不用 lambda | 严格 android.jar 缺 LambdaMetafactory（P011）|
| 不用 androidx | 无依赖仓库 |
| `java.util.Base64` 而非 `android.util` | 可在 JVM 单测（还是纯 JVM 可测的关键）|
| 不实现 MAC/root | 协议死字段（P001）|
| 发送方 = WS server | 与 CatShare 一致 |
| 等状态就绪而非等广播次数 | P2P 广播有中间态（P016）|

## 2026-10-16 CatShare 通知改造（源码路线，已完成可安装版本）

### 最终方案：只改方法体，不整类替换
经历了一轮失败（用 kotlinc 编译 89 个类整包替换 → 一装就崩）后，
**结论是：这个 APK 被 R8 激进压缩，编译期依赖库的 API 与运行时不是同一套。**
正确做法是反编译原 APK，只替换目标方法体，其余全部保持原样。

**最终产物：整个 APK 只有 2 个方法与原版不同**
```
$HOME/catshare-installed/catshare-tile.apk   (5,831,359 字节)
  ├─ P2pReceiverService.createAskingNotification   ← 重写（通知文案+按钮顺序）
  └─ AppSettings.getDeviceName                     ← 重写（默认值改读系统设置）
```

### 改动内容
| 项目 | 改前 | 改后 |
|---|---|---|
| 标题 | 发送方设备名 | `接收 N 张照片` / `接收 N 个文件` / `接收文本` |
| 正文 | `请求发送 N 个文件 - 1.2 MB` | `来自 <设备名>` |
| 按钮顺序 | 接收 \| 拒绝 | **拒绝 \| 接收** |
| 缩略图 | BigPictureStyle（会异常） | 作为 largeIcon |
| 设备名默认值 | 写死「我的手机」 | `Settings.Global.device_name` → `Settings.Secure.bluetooth_name` → `Build.MODEL` |
