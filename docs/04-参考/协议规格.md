# 互传协议规格（逆向自 CatShare + 互传联盟）

> **这是本项目的核心资产。** 任何 agent 接手前必须先读本文。

## 1. 分层

```
┌─ 发现层：BLE GATT ──────────────────────────┐
│  接收方起 GATT Server 广播；发送方扫描并连接  │
│  交换：SSID / PSK / port / (mac 死字段)      │
└──────────────────────────────────────────────┘
              ↓ 拿到 SSID+PSK
┌─ 链路层：WiFi Direct (P2P) ─────────────────┐
│  WifiP2pConfig.setNetworkName(ssid)          │
│              .setPassphrase(psk)             │
└──────────────────────────────────────────────┘
              ↓ 拿到 groupOwnerAddress
┌─ 传输层：WebSocket ─────────────────────────┐
│  ws://<groupOwner>:<port>                    │
│  自定义文本协议（见 §4）                      │
└──────────────────────────────────────────────┘
```

## 2. BLE UUID（必须完全一致才能互通）

| 用途 | UUID |
|---|---|
| 广播 Service | `00003331-0000-1000-8000-008123456789` |
| GATT Service | `00009955-0000-1000-8000-00805f9b34fb` |
| Char **状态** (DeviceInfo) | `00009954-0000-1000-8000-00805f9b34fb` |
| Char **P2P 信息** (P2pInfo) | `00009953-0000-1000-8000-00805f9b34fb` |

## 3. 数据模型

```json
// DeviceInfo —— 接收方通过 CHAR_STATUS 暴露
{"state":0,"key":"<Base64 X.509 EC公钥>","mac":"02:00:00:00:00:00","catShare":7}

// P2pInfo —— 发送方通过 CHAR_P2P 写入
{"id":"a1b2","ssid":"...","psk":"...","mac":"...","port":12345,"key":"<Base64>","catShare":7}
```

> ⚠️ **`mac` 必须是真实的 p2p0 地址**（P058 修正）。
> 小米互传会拿它去连对端；填假值（`02:00:00:00:00:00`）对方连不上就断开，
> 表现为"文件发出去了但对方没过来"，卡在版本协商超时。
>
> 而 p2p0 的 MAC 在 Android 10+ **普通 App 读不到**（SELinux 拒
> `sysfs_net`，`EACCES`），所以 **发送方向需要 root**；接收方向不受影响。

## 4. WebSocket 文本协议

格式：`type:id:name?payload`

```
正则：^(\w+):(\d+):(\w+)(\?(.*))?$
```

| 段 | 含义 |
|---|---|
| type | `action` / `req` / `resp` |
| id | 数字消息 ID |
| name | 动作名 |
| payload | 可选 JSON |

### status 消息
```json
action:<id>:status?{"taskId":"...","type":1,"reason":"ok","id":"..."}
```
`type`: `1`=成功 `3`=用户拒绝 `99`=特殊任务 ID

## 5. 加密（ECDH + AES-CTR）

```
1. 双方各生成 EC P-256 密钥对
2. 交换 Base64(X.509 encoded public key)
3. ECDH → generateSecret("TlsPremasterSecret")
4. AES/CTR/NoPadding，IV 固定 "0102030405060708"
5. 载荷 Base64 编码
```

## 6. TLS 与随包证书（★公开凭据，非私钥★）

传输层是 **TLS**（`wss://` / HTTPS），**但证书内容不被校验**。

### 对端的行为（CatShare 同样如此）

接收方用 `FakeTrustManager` + `hostnameVerifier { true }`：

```java
TrustManager[] tm = new TrustManager[]{ new X509TrustManager() {
    public void checkClientTrusted(X509Certificate[] c, String a) {}   // 全放行
    public void checkServerTrusted(X509Certificate[] c, String a) {}   // 全放行
    public X509Certificate[] getAcceptedIssuers() { return new X509Certificate[0]; }
}};
```

→ **证书只用于让 TLS 握手能建立，不承担任何身份校验作用。**

### `app/res/raw/huchuan.p12` 的定位

| 问题 | 答案 |
|---|---|
| 它是私钥吗？ | **不是**。它是自签名 TLS 证书（含配套私钥），但**没有保密价值** |
| 口令是什么？ | `huchuan` —— **明文写在 `app/src/com/huchuan/net/Tls.java` 里** |
| 和签名 APK 的密钥是一回事吗？ | **完全无关**。签名密钥在 `$HOME/.huchuan-keystore`，不入库 |
| 为什么可以入库？ | 对端从不校验它；双方都用"全信任"，等价于公开常量 |
| 证书参数 | `CN=huchuan, O=HuChuan, C=CN`；EC secp256r1；SHA384withECDSA；自签；有效期 30 年 |
| 怎么重新生成？ | `./scripts/gen-cert.sh --force` |

> **设计依据（P023）**：互传联盟的传输层是 TLS，我们必须同样提供 TLS，
> 否则对方（小米原生互传 / CatShare）连不上。而证书校验被双方一致地跳过，
> 所以随包分发一张固定自签名证书是最简且正确的做法。

> ⚠️ **重新生成会改变证书指纹**。因为对端不校验，正常不影响互通；
> 但若某个实现做了指纹绑定，需同步。改完**务必真机实传验证一次**。

## 7. 与小米互传对齐的关键点（易错）

| 项 | 正确值 | 错的后果 |
|---|---|---|
| 主广播 UUID | `000001ff-...`（公开约定） | 冒用小米私有 `0x1b1e` → Mi 15 搜不到（P106/P107）|
| GATT 特性属性 | `props=10`(READ+WRITE) / `perms=17` | 不对称 → Mi 15 搜不到（P107）|
| 设备名位置 | **自定义 service data**，不在 Complete Local Name | 对方列表显示"未知的设备"（P061/P101）|
| `/download` 时序 | 必须在 `status(1,"ok")` **之前**发起 | 发送方收到 status 就拆 P2P 组（~60ms）→ 再也连不上（P080）|
| WS 端点 | `/websocket` | 连不上（P025）|
| 单端口 | WS 与 HTTP **共用同一端口** | 对方拿同一 port 做 GET 会打到 WS → 显示"已取消"（P060）|
