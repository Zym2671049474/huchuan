## 5. ⚠️ 接手必看的四件事

### ① 硬约束（违反就编译不过或运行时崩）
| 约束 | 原因 |
|---|---|
| 不能用 lambda / 方法引用 | 严格 `android.jar` 缺 `LambdaMetafactory`（P011） |
| 不能用 androidx | 无依赖仓库（`FileContentProvider` 就是为此手写的） |
| 不能用 `android.util.Base64` | stub，纯 JVM 测试会 `Stub!`（P019）→ 用 `java.util.Base64` |
| BLE 读写必须支持 offset 分块 | 默认 ATT MTU 仅 23 字节（P018） |
| P2P 等状态就绪，别等广播次数 | 首个 `CONNECTION_CHANGED` 是中间态（P016） |

### ② 验证手段的坑
- **ART 是懒验证**："启动不崩"≠没问题（P039）。
- **系统通知不是画布**：背景色/圆角/环形进度/按钮样式都由 SystemUI 决定（P093–P097）。
- **磁贴灰掉可能是 Thanox 干的**，不是我们的 bug（P116）。
- **单机验证优先**：`./tests/run.sh` 秒级反馈。

### ③ 推送不是 `git push`
`github.com:443` **被墙**，`git push` 会永久卡住。用：
```sh
GH_TOKEN=<PAT> GH_REPO=Zym2671049474/huchuan node scripts/api-push-history.mjs
```
**优先 history 版**（保留提交历史）；老 `api-push.mjs` 会把历史压成一个提交。

### ④ 「搜不到」先看开关，别怀疑协议
10 分钟空闲**自动关**是设计行为（P123）。用户报"搜不到"时先查：
```sh
dumpsys bluetooth_manager | grep -A3 "GattServer\|Advertiser"   # 有没有 Stop time
cat /data/user/0/com.huchuan/shared_prefs/huchuan_receiver_state.xml
```

## 6. 真机排查命令

```sh
cd ~/huchuan

# 真机看日志
logcat -s HuChuan.Sender HuChuan.Receiver HuChuan.P2p \
          HuChuan.GattServer HuChuan.GattClient HuChuan.Transfer \
          HuChuan.Wire HuChuan.Tile HuChuan.RecvState
```

**日志 TAG 对照**：
`HuChuan.Sender` 发送编排 · `HuChuan.Receiver` 接收编排 ·
`HuChuan.GattClient` 扫描 · `HuChuan.GattServer` 广播 ·
`HuChuan.Transfer` 传输 · `HuChuan.Wire` 每一帧 TX/RX ·
`HuChuan.Tile` 磁贴 · `HuChuan.RecvState` 开关状态与计时
