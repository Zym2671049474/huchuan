## 一、项目定位

**互传（HuChuan）** —— 在小米 HyperOS 上与「小米互传 / 互传联盟（CatShare 协议）」互通的文件传输 App。

| 项 | 值 |
|---|---|
| 包名 | `com.huchuan` |
| 语言 | **纯 Java**（无 Kotlin） |
| 构建 | `./build.sh`（aapt2 + javac + d8 + zipalign + apksigner） |
| 产物 | `build/huchuan.apk` |
| SDK | `minSdk 29` / `targetSdk 35`（与 CatShare 一致，保证协议兼容） |
| 依赖 | **零第三方依赖** —— 见下面第 2 条，这是硬约束不是偏好 |

### 为什么必须零依赖

本机**无法解析任何依赖**：没有 Gradle 依赖仓库可用、`androidx` 不存在、
`android.jar` 是严格桩（缺 `LambdaMetafactory`，用了 lambda 就 `NoClassDefFoundError`）。
所以"引个库省事"在这里永远行不通 —— **凡是需要的，自己写**。

这也解释了为什么项目里有 `FileContentProvider`（替代 `androidx.FileProvider`）、
`ui/KnownDevices`（自己管设备缓存）、手写的 JSON / WebSocket。

## 二、硬约束（违反即构建失败或运行崩溃）

### 2.1 禁止引入的东西

| 禁止 | 原因 | 替代做法 |
|---|---|---|
| Kotlin / Gradle | 设备上不可用（P002） | 纯 Java + `build.sh` |
| `androidx.*` | 本机没有这个 jar | 自己写（如 `FileContentProvider`）|
| 任何第三方 jar | 无法解析依赖 | 手写 |
| **lambda / 方法引用（`::`）** | 严格 `android.jar` 无 `LambdaMetafactory`（P011）| 匿名内部类 |
| `java.util.function.*` 接口的 lambda 用法 | 同上 | 显式实现 |

### 2.2 平台行为约束

- **SELinux 是 enforcing**：$HOME 之外的写入会被拒；原子发布必须"写临时文件 + `rename()`"。
- **`python3` 不可用**（P013）—— 脚本改用 node 或 shell。
- **`grep` / `pm` / `settings` 的 shell shim 是坏的**（`bad interpreter`）。
  → 用 `rg`（ripgrep）、`awk`/`sed`，以及 `dumpsys` / `am` / `logcat`。
- **`ls --time-style` / `--full-iso` 不支持**（toybox）。
- **git 仓库属主问题**：仓库由 app 创建 → 所有 git 命令必须带 `-c safe.directory='*'`。

### 2.3 构建约束

- **只用 `./build.sh`**，不要手敲 aapt2/d8/apksigner 命令。
- 改动后**必须构建通过**（退出码 0）才算完成。
- `build/`、`*.apk`、`*.keystore`、`*.jks` **绝不入库**。
- **`./build.sh` 退出码必须为 0** —— 详见 P124（历史上它恒为 1，害得 CI 误判）。

## 四、文档规则

| 文件 | 什么时候改 | 强制 |
|---|---|---|
| `docs/03-进度/进度.md` | **每次提交** | ★必须★ |
| `docs/02-日志/踩坑日志-P054-P125.md` | 踩到新坑时（加在最上面） | 踩坑时 |
| `docs/02-日志/测试日志.md` | 跑过测试后（追加） | 跑测试时 |
| `docs/04-参考/协议规格.md` | 协议有变化时 | 协议改动时 |
| `docs/01-规范/*` | 规则本身变化时 | 极少 |
| `README.md` | 项目定位/用法变化时 | 定位变化时 |

### 踩坑条目的格式（缺一不可）

```markdown
## P<编号> · <一句话结论>

**现象**：观察到什么（带原始日志/报错）

**根因**：为什么

**解法**：怎么改的

**证据**：怎么证明改对了
```

- **编号连续递增**，跨文件不重复、不回收。现行下一个是 **P126**。
- **结论要写成"可判定"的句子**（"广播 UUID 必须用 0x01ff"），
  不要写"研究了广播 UUID"这种没有信息量的话。

### 文档纪律

- **不写猜测**：没有证据的结论标注 `（未验证）`。
- **推翻旧结论时要显式标注**：如 P058 有两版、P094/P095 被 P096 推翻 —— 保留错误版本并说明为什么错，这比删掉更有价值。
- **进度.md 是单一事实源**：状态只在那里维护，不在别处复制一份。

## 五、代码规范

- **Java 8 语法**（`-source 8 -target 8`），不用新语法糖。
- 命名：类 `PascalCase`，方法/变量 `camelCase`，常量 `UPPER_SNAKE_CASE`。
- **日志**：`android.util.Log`，`TAG` 统一 `HuChuan.<模块>`：
  `HuChuan.Sender` / `HuChuan.Receiver` / `HuChuan.P2p` / `HuChuan.GattServer` /
  `HuChuan.GattClient` / `HuChuan.Transfer` / `HuChuan.Wire` / `HuChuan.Tile` / `HuChuan.RecvState`
- **并发**：跨线程共享的字段加 `volatile`；共享的可变状态优先收敛到单一类
  （如 `ReceiverState`），不要散落 static。
- **异常**：`catch (Throwable ignored)` 只在确实要吞的地方用，且必须写清为什么能吞。

### 必须遵守的两条经验

1. **每个提交都要能独立构建**（P125 的教训：中间提交缺文件，`git bisect` 会失效）。
2. **改动要对照 CatShare 源码验证**，参考实现在 `$HOME/CatShare-src/`。
   与"照抄小米互传"有关的设计，务必在注释里写明依据。

## 六、测试与验证

### 分层验证（从快到慢）

| 层 | 命令 | 需设备 | 用途 |
|---|---|---|---|
| 单测 | `./tests/run.sh` | ❌ | 协议编解码、加密等纯逻辑，**改完必跑** |
| 构建 | `./build.sh` | ❌ | 编译/打包/签名，**退出码必须 0** |
| 装机 | `./build.sh install` | ✅ | 真机验证 |
| 双机 | 见 `docs/04-参考/双机测试指南.md` | ✅✅ | 端到端互传 |

### 验证纪律

- **`./tests/run.sh` 必须保持全绿**（当前 10/0）。改了协议相关代码务必先跑它。
- **不要用推测代替复现**（P027 是整段弯路的总根因）。
- **"改动被派发了"≠"功能生效"** —— 任何关键改动都要有**实测证据**（日志/文件字节数/截图）。
- **测试不要用 `am` 模拟启动服务**（P053 会制造假故障），走真实流程。
- 每次真机测试后 **`am force-stop` 复位**，别把 app 留在坏状态。

## 七、签名与密钥

| 项 | 位置 / 值 |
|---|---|
| 构建密钥库 | `$HOME/.huchuan-keystore`（**仓库外**，缺失时 `build.sh` 自动生成）|
| 口令 | 环境变量 `HUCHUAN_KS_PASS`，默认值见 `build.sh` |
| 别名 | `huchuan` |

- **私钥绝不入库**（`.gitignore` 已覆盖 `*.keystore` / `*.jks`）。
- **换密钥 = 不能覆盖安装**（签名不符），换之前想清楚。
- `app/res/raw/huchuan.p12` 是**协议必需的公开凭据，不是私钥** ——
  它是对端**从不校验**的自签名 TLS 证书，密码就写在 `Tls.java` 里。
  详见该文件头注释与 [协议规格](../04-参考/协议规格.md)。

## 八、Git 规范

### 提交信息

```
<type>: <一句话说清做了什么>（P<编号>）

<可选：为什么这么改、证据>
```

| type | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 只改文档 |
| `build` | 构建脚本 |
| `refactor` | 重构（不改行为）|
| `test` | 测试相关 |
| `chore` | 杂项 |

**铁律：每次提交都要更新 `docs/03-进度/进度.md`。**

### 推送

`github.com:443` **被墙**，**不要用 `git push`**（会永久卡住）。
用 API 脚本，见 [推送指南](../04-参考/推送指南.md)：

```sh
GH_TOKEN=<token> GH_REPO=Zym2671049474/huchuan node scripts/api-push-history.mjs
```

- **优先 `api-push-history.mjs`**（保留提交历史）；
  `api-push.mjs` 会把历史压成一个提交，只在同步"快照"时用。
- token 只走环境变量，**绝不写进文件或提交**；用完立即 revoke。
