# 推送指南

## ⚠️ 本网络环境的关键事实

**`github.com:443` 被墙，但 `api.github.com` 可达。**

| 端点 | 状态 |
|---|---|
| `api.github.com:443` | ✅ 可达 |
| `github.com:443` | ❌ **不可达** |
| `codeload.github.com` | ❌ 不可达 |
| `ssh.github.com:443` | ✅ 可达 |

**结论：不要用 `git push`**（会卡住或超时）。用 API 推送。

## 推送方式

```sh
cd <repo>
GH_TOKEN=<你的token> GH_REPO=Zym2671049474/huchuan node scripts/api-push-history.mjs
```

### ★用哪个脚本★（P124）

| 脚本 | 行为 | 何时用 |
|---|---|---|
| `scripts/api-push-history.mjs` | **按本地提交逐条重放**，远端历史与本地**完全一致** | ✅ **默认用这个** |
| `scripts/api-push.mjs` | 把**整段历史压成一个提交**（只取 `git log -1` 的 message） | 仅在只想同步"最终快照"时 |

老脚本的做法是 `git ls-files` 一次性建一棵"当前工作区"的树 + 单父提交，
所以本地 4 个提交推上去只剩 1 个。**要保留提交历史就用 `api-push-history.mjs`。**

新脚本走 Git Data API，全程只访问 `api.github.com`：
```
对每个待推送提交:
  GET  /git/ref/heads/main           ← 取远端 head 作起点（一次）
  POST /git/blobs                    ← 逐文件上传（base64）
  POST /git/trees                    ← 建该提交自己的树
  POST /git/commits                  ← 建提交（父=上一个新 sha）
最后:
  PATCH /git/refs/heads/main         ← 全部建好后**才**动分支
```
> 最后一步才更新分支，所以中途失败**不会**把远端留在半截状态。

**注意**：脚本推送的是**已提交的内容**，所以先本地 commit 再推送。

## 工作流

```sh
cd ~/huchuan
./build.sh                       # 1. 确保能构建（退出码 0 = 成功，见 P124）
./tests/run.sh                   # 2. 纯 JVM 单测
git add -A
git commit -m "feat: xxx"        # 3. 本地提交（并更新 docs/进度.md）
GH_TOKEN=xxx GH_REPO=Zym2671049474/huchuan node scripts/api-push-history.mjs   # 4. 推送
```

## 常见错误

| 错误 | 原因 | 解法 |
|---|---|---|
| `409 Git Repository is empty` | 空仓库不能建 blob | 先用 contents API 建 `.gitkeep`（已做过）|
| `422 Reference already exists` | `main` 已存在 | 脚本已改为 `PATCH` 优先 |
| `ENOENT: docs/\345\215...` | git 八进制转义中文名 | 脚本已加 `core.quotepath=false` |
| `Failed to connect ... github.com:443` | 被墙 | **别用 git push**，用本脚本 |

## token 安全

- **绝不**把 token 写进文件、`.git/config` 或提交
- 用环境变量传入，脚本只在内存中持有
- 万一泄漏：GitHub → Settings → Developer settings → 立即 revoke

## 注册 SSH key（备选方案，本项目未采用）

`POST /user/keys` 返回 404 是因为 token 缺 `admin:public_key` scope。
如需 SSH 方式，须用 classic token 并在网页端手动添加公钥。
